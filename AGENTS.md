# Правила учебного примера

## Текущая ветка: ступень 3

- Ветка `course/example/stage-3-reset-years` продолжает собственный результат ступени 2 в этом же репозитории. Ниже сохранены правила исходной ступени 1; ограничения «на этой ступени» относятся к ней, а не к текущему переходу.
- На ступени 3 разрешена подготовка OpenSpec для накопительных требований и планирования. Код приложения не добавлять и не менять, Apply не запускать.
- Перенос всех восьми исходных сценариев проверен в `openspec/changes/add-reset-and-years-term/traceability.md`. Рабочий источник требований — спецификация этого Change; `specification.md` доступен в истории по SHA R2 `3b72edc68ba14bc4bc947c8b0dcfbcc4343e0977`. Не восстанавливать вторую рабочую копию ТЗ.
- Описанные требования не считать реализованными: в этой папке нет кода сервиса и доказательств его работы. Все задачи будущей реализации остаются незавершёнными.
- ИИ-проверка не заменяет человеческое ревью. Работать только в персональной ветке; не сливать учебные изменения в общую `main` эталона.

## Исходная ступень 1

- Учебную работу ведите в персональной ветке. Не отправляйте её напрямую и не сливайте в общую main эталона. Результат этой ступени — личный коммит `specification.md` и его полный SHA; PR не требуется. Сопровождение эталона владельцем — отдельная задача.

- Работайте с specification.md и заданием из README.md.
- Вопросы, на которые нет ответа, показывайте человеку до правки требований.
- ИИ предлагает изменения; человек принимает решения и проверяет документ.
- Не добавляйте код приложения, npm-инструменты или OpenSpec на этой ступени.
- Не реализуйте требование в калькуляторе: все четыре учебные ступени готовят накопительное ТЗ.
- Не выдавайте чтение документа за запуск тестов или человеческое одобрение.
- Не сохраняйте секреты, персональные данные и корпоративные документы.
