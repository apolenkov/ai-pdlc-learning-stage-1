# Шаг 3: изменение в OpenSpec в этом же fork

После шага 2 маршрут продолжает обязательный [шаг 3 «Изменение в OpenSpec»](https://apolenkov.github.io/customdev-learning/guides/s3-openspec.html); основы SDD и OpenSpec вы уже прошли в [подготовке](https://apolenkov.github.io/customdev-learning/guides/p3-sdd.html). Шаг ручной: он полезен и для работы без модели. Не клонируйте сервисный пример и не добавляйте приложение ради этого шага.

Шаг 3 выполняется веткой `course/your_login/stage-3-reset-years` от принятого шага 2. До инициализации обновите `AGENTS.md` под правила шага 3. Точную разовую инициализацию OpenSpec под Kilo выполняйте в этом же checkout по полной инструкции шага 3: она вызывает `openspec init --tools none`; последовательность команд здесь не дублируется. Три навыка планирования лежат в репозитории в универсальном `.agents/skills` (`openspec-explore`, `openspec-propose`, `openspec-update-change`) — этот каталог автоматически читают Kilo и другие агенты, поэтому дублировать навыки под конкретный инструмент не нужно. Для Kilo в VS Code дополнительно лежат команды `.kilo/command` (`opsx-explore`, `opsx-propose`, `opsx-update`). Навыки переходят с принятыми ветками шагов 1–3, генерировать или копировать их не нужно. Полный `openspec init --tools kilocode` не запускайте: он развернёт все рабочие процессы, а шаги 1–3 ограничены планированием.

Далее запрашивайте `status` и `instructions` для следующего документа планирования и заполняйте его сами. Переносите все восемь сценариев шага 2 поэтапно. Удаляйте рабочую `specification.md` только после таблицы соответствия и строгой проверки полного Change; в таблице запишите репозиторий, принятый PR (MR) шага 2 и личную ветку — точный коммит при необходимости выводится из проверенного PR (MR), а полный SHA остаётся необязательной продвинутой фиксацией. В этом учебном репозитории нет доказанного рабочего состояния: новые функции остаются в активном Change с незавершёнными задачами. Apply запрещён. Если CLI недоступна, init завершился ошибкой или root оказался другим, остановитесь и следуйте разделу устранения ошибки полной инструкции; не создавайте структуру наугад.

На шагах 1–3 можно работать вручную. Если используете ИИ как помощника, проверяйте его предложения и сохраняйте решение в том же документе и текущей ветке; отдельные AI-ветки и параллельные учебные задания не нужны. ИИ не принимает решение за владельца и не заменяет одобрение владельца продукта по текущему diff.
