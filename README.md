# Ступень 1. Спецификация в Git

Результат: своя ветка с уточнённой specification.md и понятной историей решения. Нужны Git, редактор Markdown и доступ к учебному репозиторию. Node.js и OpenSpec не требуются.

Клонируйте [учебный репозиторий](https://github.com/apolenkov/sdd-guide-credit-calculator-stage-1) и откройте его папку:

```bash
git clone https://github.com/apolenkov/sdd-guide-credit-calculator-stage-1.git
cd sdd-credit-calculator-stage-1-example
```

Репозиторий приватный: организатор обучения выдаёт доступ на чтение и отправку учебных веток. Если папка уже открыта, начните с задания ниже.

## Задание

В командах замените `your_login` на свой GitHub-логин. Так у каждого участника своя ветка. Для повторного прохождения добавьте к ней суффикс `-2` и используйте новое имя в push. Не отправляйте учебное решение напрямую и не сливайте его в общую `main`: она остаётся исходным эталоном.

Прочитайте [спецификацию](specification.md). В разделе «Открытые вопросы» есть конкретная развилка: что делать с предыдущим результатом после ошибки.

Учебное решение для этого упражнения: очищать предыдущий результат и показывать «—». Это заданное условие упражнения, а не факт, который нужно угадать.

1. В терминале корня репозитория создайте ветку:

   ```bash
   git switch -c feature/your_login/error-result
   ```

2. Дополните требования: при ошибочном вводе сообщение указывает проблемное поле, а предыдущий результат заменяется на «—».
3. Добавьте сценарий: сначала 120 000 ₽, 0%, 12 месяцев → 10 000 ₽; затем срок 1,5 месяца → ошибка и «—» вместо результата.
4. В «Открытых вопросах» замените решённый вопрос на «Для данного упражнения открытых вопросов нет».
5. Сверьте, что новое правило, сценарий и итог раздела вопросов не противоречат друг другу. Проверьте формат и список правок:

   ```bash
   git diff --check
   git diff -- specification.md
   ```

6. Сохраните принятые правки:

   ```bash
   git add specification.md
   git commit -m "docs: clarify result after invalid input"
   ```

Если Git сообщает, что имя или почта автора не настроены, настройте свою рабочую учётную запись по правилам команды. Не копируйте чужие данные.

## Результат проверки

В diff есть правило очистки результата и один новый сценарий. Исходные четыре сценария сохранены. Ошибка команды или открытый вопрос не считаются успешной проверкой. На этой ступени вы проверили спецификацию, а не реализацию калькулятора.

Отправьте свою ветку командой `git push -u origin feature/your_login/error-result`. В учебную задачу Jira добавьте ссылку на ветку и краткое описание принятого решения; название задачи — «Уточнить поведение результата кредитного калькулятора при ошибке», проект DEMO, родитель DEMO-1. Если задача ещё не создана, сначала создайте её с этой целью.
